# 版本规则与当前实现

包版本为 `0.0.1-beta`，网络协议主/次版本为 `0.0`，C ABI 独立为 1.0。正式发布尚未执行。

## X.Y.Z-beta 契约

- X 不同：业务 wire 协议绝不互通；握手版本发现必须跨 X 可读，可并存多个版本实现并选择匹配版本。
- 同 X 不同 Y：低 Y 忽略高 Y 的未知可选内容，高 Y 可完整兼容低 Y 数据；新增字段须有明确的长度、可跳过规则和默认语义，不得变更既有内容含义。未知必需语义须拒绝而非误处理。
- Z 改变：网络协议内容不变，仅内部实现或 API 变更；必须保留 wire 和跨补丁互通测试。
- beta 是发布阶段标识，不是可绕过兼容规则的许可。包版本、网络版本和 C ABI 版本的职责不同。

## 实现缺口

当前 HELLO 只携带 X/Y，当前实现严格校验这两个值并要求固定长度；HELLO_ACK 不提供双方版本发现结果，尚无跨 X 发现、自动切换或跨 Y 可跳过扩展。不得声称这些能力已经实现。必须先冻结跨 X 稳定的发现信封与对称握手、扩展编码和互通矩阵，再实现并验证后续不同 X/Y 版本。两个不同版本 crate 并存还需处理 Rust 包解析、C 符号冲突和共享句柄边界。

当前 0.0.1-beta 是首次发布候选，网络线格式与此前未发布的 1.0 实验握手有意不兼容；这不是与既有用户版本的兼容承诺。

## 平台状态

每个 Endpoint 一个 UDP socket。Windows 使用软件发送分段能力探测和回退；Linux/Android 等待源使用 eventfd；macOS/iOS 使用可等待 pipe 和宿主 kqueue 用户事件。Tokio 使用平台反应堆；不要把 kqueue 通知声称为原生 UDP 批处理或零拷贝。WSL 是 Linux 内核测试而非独立 Linux 硬件；macOS 结果以实际 CI 为准。
